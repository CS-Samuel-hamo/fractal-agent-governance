# DeepSeek Execution Compensation Policy

DeepSeek V4 Flash is allowed to perform low-risk, bounded, verifiable work. Its compensation layer is not a list of special cases. It is an obligation expansion protocol.

## Required Compensation

Before coding, DeepSeek must produce or update the Obligation Ledger, search existing patterns, identify propagation surfaces, identify verification obligations, and define rollback evidence. It may not implement only the literal function while leaving required propagation obligations unresolved.

## DeepSeek Must Escalate

Escalate to GPT when obligation meaning is unclear, project patterns conflict, data-source semantics differ, architecture boundary is unknown, security/auth/PII/payment/migration is involved, test command is unknown for non-trivial coding, quality gate fails repeatedly, or branch scope exceeds the contract.

## Anti Self-Approval

DeepSeek may draft obligation discovery, plans, status, risk, mechanical review, and release readiness summaries. GPT or human authority must approve final planner, final reviewer, final integrator, final curator, architecture/security/release decisions, and human exceptions.
